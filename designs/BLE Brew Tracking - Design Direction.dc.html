Design direction · Parent #43

BLE brew-tracking feature set

Bookoo Scale + Espresso Monitor connection, a Timer-page telemetry/chart experience, and a Visualizer.coffee ghost-curve picker — built entirely from BrewMe's existing Material tokens and components. No new design system, no working code yet.

Assumptions, from your answers
  • Bookoo Scale and Espresso Monitor are fully separate connect flows — no shared "device" abstraction, just two independent rows/pills.
  • Stop/Seal sends a stop command to every connected device and ends recording — distinct from Reset (discards) and Play/Pause (timer-only, no hardware effect until connected).
  • Once any device is connected, Play/Pause's running state is replaced by Stop/Seal — no ambiguous "paused but still recording" hardware state.
  • Ghost curve can be picked before brewing and swapped mid-brew; it always overlays the live curve.
  • Extraction chart is hidden entirely until a device has connected at least once this session — no empty dashboard for pour-over-only users.
  • Visualizer.coffee browser is designed against a real-looking API surface: search, tags, author, machine/grinder filters.
  • Expanded (≥840px) layout splits the Timer page into two columns: dial + controls left, chart + telemetry + ghost picker right.
  • Revised: unsupported browsers (iOS Safari, Firefox) don't get a visible "unsupported" state — the whole BLE surface (Settings section, Timer banner, pill) is feature-detected out, so those users just see today's app.

One new primitive — nothing today renders a colored state badge. Compact (dot + label) so it drops into a banner row or a stat tile header without competing with the numbers next to it.

5 · Stop/Seal state logic

Reuses the existing fab slot and icon-button styling — no new button style. It's a swap of what occupies the center fab, not a fourth control.

No device connected
Fab is Play → Pause → Play, exactly as today. Nothing changes for manual brewers.
Device connected, idle
Fab is Play. Tapping it starts the timer and begins device recording.
Device connected, running
Fab becomes Stop/Seal (filled square icon, same primary-container fab). Tap sends stop to every connected device, ends recording, and stops the timer — no pause state in between.

7 · Visualizer.coffee profile picker

brew-bottom-sheet (bottom sheet on phone, centered modal ≥840px, already responsive) holding a search field, filter chips, and a result list — the same browse→tap→select shape as the existing saved-brew/recipe picker sheets. brew-empty-state covers no-results and offline.

Handoff notes
  • New primitive: the status pill (dot + label, 3 states — disconnected / connecting / connected). Everything else is existing components used as documented.
  • Gate all BLE UI behind a single "bluetooth" in navigator check at the app-shell/store level so Settings, Timer banner, and pill all agree — no per-component feature detection drifting out of sync.
  • Verify stat-tile's existing props before building new telemetry tiles — it looks like the same value+label shape.
  • Bluetooth/scale/gauge icons above are placeholders — swap for the app's real Material Symbols glyphs at build time.
